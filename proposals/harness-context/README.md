# Give each agent the instructions its job needs

## Actor, result and example

Brian wants a harness that follows his rules without making every job carry every procedure. The coordinator keeps the outcome and routes bounded jobs; native specialists load the shared safety core, their role, the target repository authority, and only the procedure activated by that job.

A successful result looks like this: Brian asks why maintenance-worktree refuses the documented command. The coordinator sends only the failure packet and the two source paths to development-investigator. The investigator returns the default broad scope, the rejecting admission condition and the missing recovery variable with exact locators, leaves the target unchanged, and its native trace shows the omitted workspace procedure payload and measured initial input. Brian sees that explanation and the bounded-context receipt on the review page.

The first example is a real failure from this audit: an agent follows the documented maintenance-worktree command and gets a broad-scope refusal without the path variable that would recover it. The coordinator gives a read-only investigator the exact source revision, the observed refusal and the allowed implementation paths. The investigator must identify the default write scope and its admission check, cite both sources, and return uncertainty if that packet cannot establish the cause. It must not create claims or fix files.

## Success, disproof and checks

Full execution traces for every runnable criterion live in this Codex session (01a1198b-539e-7d32-8dc4-7fe62cc903d9 and its named specialist children) in the native client transcript store. evidence.json indexes each exact transcript path and step range, source revision, command input, complete stdout/stderr or browser event trace, outcome and parent inspection. The full gate and inventory command transcripts are retained there beyond counts. The parent reads the complete selected inventory-generation/check run, final local-gate run and browser journey: inspect target resolution, discovery/exclusion decisions, tool/command sequence, skips, source inputs, tooltip interactions, evidence links and failures as well as the final outcome. Raw traces stay in their owning bounded runtime store; compact redacted extracts remain beside this plan.

- Inventory: every registered accessible instruction, shared/derived/plugin skill, hook/policy/command entrypoint has a row with requirement, enforcement, discovery, cost method, duplication/conflict, parity and friction. The full inventory-generation and semantic-enrichment run trace is retained in the named native specialist transcript, shared llm_client trace store and systemd job journal, indexed by evidence.json. Inspect every command/tool step, discovery/exclusion input, complete stdout/stderr, skipped row, source identity and semantic call/output; the two inventory JSON files retain compact metadata only and are not substitutes for that full trace. A scan that omits both AGENTS and CLAUDE when both exist fails.
- Findings and repairs: findings name evidence, context/runtime or human cost and smallest fix; the full run trace is the original detecting output, source writer, fix diff and recheck stored in evidence.json. An ownership boundary or deliberately disabled mechanism is a named disposition with its issue, not a successful repair.
- Canary: run the native client through the real role and task described above. Full trace remains at the client's recorded session path; the compact receipt records that path, inspected steps, role/source digests, loaded-context evidence, input usage and causal locators. Look beyond the final answer for tool selection, target identity, instruction delivery and forbidden writes. Effective loaded context or native usage must support any specific shrink claim. Byte estimates alone never establish savings; any unproved client remains explicitly unproved.
- Local gates: renderer/check tests first, then the owning repository's complete local merge checks once for the final candidate. Keep counts and exit status in evidence.json; inspect failed/skipped cases and never call an all-skipped run support.
- Human surface: open review-page/index.html through a browser at desktop and phone widths; inspect the layered architecture, selected specialist details, evidence links and visible tooltips for every control. Retain browser outcome and screenshot paths with the page disposition. Pure design prose has a no-run exemption because its artifact is read directly; the runnable page and canary do not.

Disproved if the specialist receives the omitted global procedure payload despite a shrink claim; lacks a necessary invariant; edits an unowned target; its source-linked explanation disagrees with the failure-producing writer; or a reported enforced control cannot fail under its negative control. A single successful canary proves only this task and client configuration, not a general runtime or speed improvement. Context reduction is computed per native trace as baseline effective input minus specialist effective input, with cache reads/writes reported separately; record the prompt/tool/repository differences and make no average-latency claim.
