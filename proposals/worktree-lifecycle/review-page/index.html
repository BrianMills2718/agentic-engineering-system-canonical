How do worktrees stop piling up?

Create each task in the right place. Close it only when its work is recoverable. Keep active work and running services with an explicit reason.

Safe to close?

Check ownership, saved work, and services using the folder. A clean folder or an expired claim is not enough. Uncertainty keeps the worktree in place.

Fix the cause, then resolve the leftovers

The October 8 investigation found 60 linked worktrees, including 29 with changes. Those are a dated baseline, not a deletion list. Standard folders inside repositories are intentional. Success means every remaining worktree has a reason, owner, and next event.
