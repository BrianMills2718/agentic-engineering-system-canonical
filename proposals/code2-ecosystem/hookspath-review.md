# Repositories with a local git hooks path (R6)

Git runs hooks from exactly one folder. Most repositories under `~/code` use the shared folder
`~/.config/git/hooks`. The 34 below override it with a local `core.hooksPath`, so the shared
hooks do not run there unless something forwards to them. This page lists each one, why it
overrides the shared folder, and what phase 2 should do with it.

How the rows were produced (2026-10-13): for every `~/code/*` repository,
`git config --local core.hooksPath`, `git config --local aes.originalHooksPath`, the files in both
folders, and whether each wrapper file says `Generated by install_everywhere`. The plan counted 32
repositories when it was adopted; on 2026-10-13 there are 34.

**Why they override it.** AES's rollout installer
(`proposals/aes-planning/rollout/install_everywhere.py`, 2026-10-07) found repositories whose own
hooks already lived in a tracked folder (`aes.originalHooksPath`). It could not point them at the
shared folder without dropping their own hooks, so it gave each a generated wrapper folder,
`~/.config/git/hooks-local/<repo>/`. In that folder `commit-msg` runs the AES commit rule and then
the repo's own hook, and every other hook runs the repo's own hook unchanged.

**What this means.** The AES commit rule runs in every wrapper repository, so the earlier claim
that these repositories skip the shared rules was wrong for the commit rule. What they do miss is
the rest of the shared `pre-commit` (the canonical-checkout warning and the observation log).
`agentic-engineering-system` is the one exception: its local setting points at the shared folder
itself, so it already runs every shared hook and the local setting is only redundant.
