Feedback coverage: every part of the agent setup, and what feedback reaches it

An audit of the whole setup, not a list of guesses. The parts were found from the setup's own inventories (policy registry, component inventory, hook and plugin configs, 58 scheduled jobs), and the feedback routes from every program that records something about agent behaviour. Result: 16 routes record feedback; none of them changes a rule file by itself. Every change still needs an agent to make it, and almost all happen because you asked in a chat.

Checked 11 October 2026. Companion pages: the whole picture (counts) and domain and data-flow models.

What the audit concludes

  • Recording is broad; applying is missing. 16 routes capture feedback, but every one ends at a file, a report or an issue. The one exception writes skill drafts that nobody installs.
  • The missing piece is an owner per surface. Each row needs someone (an agent on a schedule) who reads that surface's feedback, makes or rejects the change, and records the result so the effect can be counted.
  • Two big stores are never read: the tool-gate decision log (124 MB) and the commit-rule daily report.
  • Two systems do the same job: the old project-meta friction clusters and the new feedback loop both turn friction into concerns.
  • Prose carries half the rules: 135 of 263 policies have no check behind them, so feedback that a policy is ignored has nowhere to go but more prose.

How this was checked

Parts of the setup: enforcement channels and layers counted in project-meta/policy/registry.yaml; component types in agent-skills distribution/component-classification-report.md; .rulesync/; client hook files and plugin lists (keys and counts only); systemctl --user list-timers with each unit's command. Feedback routes: each program's source and its last run (journalctl --user, file dates, git logs); the 24 "Feedback loop: adopt" issues. Re-checked by hand: memory index (62 links, 30 missing), tool-gate log size (124,219,368 bytes), aes-gate-watch failure (12:11 today). One finding was retracted: Codex does not cut off AGENTS.md (its limit is 131,072 bytes; the file is 48,015).
