Agent feedback: where it goes, how it gets there, where it stalls

Agents write feedback lines at the end of each task. A nightly job copies them into one private GitHub repository. A weekly job groups repeats into problems. The last steps, turning a problem into an enforced fix and checking it worked, have not happened yet: 0 fixes enforced so far.

Numbers as of Sunday 11 October 2026, from the jobs' own run logs (sources at the bottom). Counts only; no feedback text is on this page. Tap or hover any box for details.

What counts as one report

A Feedback section. Every agent reply that finishes a piece of work ends with a "Feedback:" field, one line per thing the agent noticed, each with a link to evidence. One reply = one report, filed as one issue. Example line: obs (control): a weekly job failed with exit 2 and raised no alert [project-meta#2538].

A chat message from you. A small model reads your messages in each session and keeps the ones it judges to be a correction or direction, word for word. Each kept message = one report.

A subagent finishing. When a helper agent ends, a line about how it ended is written automatically. Each = one report.

Why "51"? 51 is the number of conversations (session files) that changed since the night before, not replies. Those 51 conversations held 981 reports: 341 Feedback sections, 211 of your messages, 426 subagent lines, 3 older-style sections.
