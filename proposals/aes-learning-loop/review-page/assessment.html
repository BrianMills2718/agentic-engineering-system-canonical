Questions worth asking of it

What decision does a Feedback line change?

The design optimises capture: every turn must write one, and "None" is discouraged. But the scarce step is turning a recurring problem into a check that works. Since 10-08 that has happened about once. More lines do not speed that up; they slow grouping down.

Are two sightings really independent?

"Independent" means different session or day. But every agent reads the same AGENTS.md and skills, so one bad instruction produces many sightings of one cause. That is the signal you want for "this instruction is wrong", but it is not two independent confirmations of a proposed fix.

Should transcript mining and the Feedback field overlap?

The collector already mines transcripts for your messages and subagent outcomes. If code can see it, the agent doesn't need to restate it. The field could hold only what the transcript cannot show: the agent's own belief about a cause, and what it tried.

Why build "did it work?" from scratch?

Error trackers solved this exact shape years ago. Sentry groups events by fingerprint, an issue is marked "resolved in" a release or commit, and if the same fingerprint appears after that, it is flagged a regression and reopened. GitHub already records which pull request closed an issue, which gives the revision and date without any hidden comment.
