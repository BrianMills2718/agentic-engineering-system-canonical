5. What data passes between the functions

Each box is one function. A wire means one function's result is the input another one needs, matched by type. Built from typed signatures in the plan. A grey stub on top of a box is an input nothing here produces: it comes from outside. Solid outline: added by this proposal; dashed outline: existing. Tap a function to see the file it lives in. On a phone each function is one line: what it takes and from whom, what it gives and to whom.

  • load_target Records
    takes nothing from the functions here
    gives TargetRecord to review_points_of, review_point_findings
  • load_proposal Planning
    takes nothing from the functions here
    gives Proposal to review_subject
  • gate_violations Planning
    takes list[GateFinding] from reference_findings (or another function giving the same type); list[GateFinding] from review_point_findings
    returns list[str] (used outside this drawing)
  • assess Evidence
    takes nothing from the functions here
    gives EvidenceReport to derivation_lens
  • review_subject Review
    takes Proposal from load_proposal
    gives ReviewSubject to derivation_lens, port_graph, reference_findings
  • derivation_lens Review
    takes ReviewSubject from review_subject; EvidenceReport from assess
    gives DerivationGraph to render_review
  • port_graph Review
    takes ReviewSubject from review_subject
    gives PortGraph to layout_ports, reference_findings
  • layout_ports Review
    takes PortGraph from port_graph
    gives PortLayout to render_review
  • reference_findings Review
    takes ReviewSubject from review_subject; PortGraph from port_graph
    gives list[GateFinding] to gate_violations, render_review
  • render_review Review
    takes DerivationGraph from derivation_lens; PortLayout from layout_ports; list[GateFinding] from reference_findings (or another function giving the same type); list[ReviewPoint] from review_points_of
    gives ReviewPage to write_review
  • write_review Review
    takes ReviewPage from render_review
    returns Path (used outside this drawing)
  • review_points_of Review Points
    takes TargetRecord from load_target
    gives list[ReviewPoint] to render_review, review_point_findings, render_check
  • review_point_findings Review Points
    takes list[ReviewPoint] from review_points_of; TargetRecord from load_target
    gives list[GateFinding] to gate_violations
  • render_check Review Points
    takes list[ReviewPoint] from review_points_of
    gives RenderResult to observe_render
  • observe_render Review Points
    takes RenderResult from render_check
    returns Path (used outside this drawing)
