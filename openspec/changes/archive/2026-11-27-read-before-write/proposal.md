## What Changes

- New command `lockstep reads TRANSCRIPT [--repo PATH] [--json]` (module `lockstep.read_before_write`). It reads
  a Claude Code transcript or `claude -p` stream, or a Codex rollout or `codex exec --json` stream, and lists each
  write to a file in the repository with three marks: the file was read earlier in the session; its requirement
  context was read earlier (the file's capability page under `generated/wiki/` or that capability's
  `openspec/specs/<capability>/spec.md`); the edit hook handed over requirement text on that write.
- It prints a warning line for each write to an existing file with neither read, and one `RESULT` line with the
  counts. It exits 0 whatever it finds: it reports, it never blocks.
- No hook changes: the session file already holds every read and write, so the hooks' footprint stays as it is
  (Brian turned all hooks off in September 2026 because they got in the way; agent-skills
  `contracts/client-config/hooks-not-enabled.json`).

## Impact

- Known gap: an edit made by a script inside a shell command (`python3 - <<EOF ... open(p, 'w')`) is not
  counted, because the parser cannot tell which named path it writes.
- New: `src/lockstep/read_before_write.py`, `tests/lockstep/test_read_before_write.py`, one `cli()` branch in
  `src/lockstep/check.py`.
- The replay viewer (Milestone 1 step 8) reads the `--json` output to mark each write.
