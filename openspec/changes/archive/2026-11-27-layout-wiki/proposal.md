## What Changes

- New module `lockstep.layout_wiki` renders, from data Lockstep already reads (OpenSpec requirements, `Implements:`
  docstring blocks, `@pytest.mark.req` tags, layout rows), `generated/wiki/index.md` (one line per capability) and one
  page per capability. It reads the existing parsers; it adds no second one.
- `lockstep check project` writes those pages and `--check` fails when they are stale or fail the existing wiki
  reachability and summary rule. It is on only where `lockstep.yaml` says `generated_wiki: true` (inferred by agent: it
  keeps every other layout repository's `project --check` passing until it opts in).
- Files under `generated/wiki/` need no layout row, and the Markdown cap already skips `generated/`; a test now pins that.
- `python -m lockstep.wiki` prints the generated pages in a layout repository.
- The copier template sets `generated_wiki: true`, commits the pages, runs the reachability check and `docmeta` in
  `make check`, and tells agents to read `generated/wiki/index.md` first.
- The refusal requirement no longer says `python -m lockstep.wiki` "needs an AES plan" (it no longer does).
