## Why

The generated wiki pages (#1085) show coverage only: which code implements each requirement and which tests are tagged.
They cannot show pass or fail, because a committed page that says "passing at commit X" is wrong as soon as it is
written: writing it dirties the tree and committing it moves HEAD off X, and `lockstep status` trusts results only at
HEAD on a clean tree (`src/lockstep/checks/status.py`, `_results`). The plan status blocks have the same limit. An agent
reading the wiki first therefore cannot see which requirements pass. Brian, 2026-11-27, plan doc "AES next steps: plan
for discussion", Milestone 1 step 2 (write pass or fail back, "tests pass at <commit>"); decision 12 (results kept
outside git, shown when regenerated); told the agent to proceed without waiting.
