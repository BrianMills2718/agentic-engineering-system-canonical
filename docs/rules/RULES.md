# Rules agents follow

Every rule agents in Brian's workspace are expected to follow, how each one is enforced, and where its evidence is. Generated by `scripts/rules/build_rules_page.py` from [the AES rules register](register.yaml) and, read-only, project-meta's legacy register; edit the register, not this page.

| Section | Rules | How they are enforced |
| --- | --- | --- |
| [Rules in the workspace instructions](#rules-in-the-workspace-instructions) | 12 | 2 enforced, 1 partially-enforced, 1 checked, 8 advisory |
| [Rules from the feedback loop](#rules-from-the-feedback-loop) | 21 | 3 enforced, 15 licensed, 3 withdrawn |
| [Legacy project-meta register](#legacy-project-meta-register) | 263 | 40 enforced, 40 partially-enforced, 13 checked, 169 advisory, 1 planned |

What the statuses mean: **enforced**: a hook, gate or check refuses the violation; **partially-enforced**: enforced on some paths only; **checked**: a check reports violations but does not refuse them; **advisory**: written instruction only; **licensed**: the feedback loop licensed it from evidence and handed it to agents; not yet adopted; **withdrawn**: licence withdrawn; kept for the record.

## Rules in the workspace instructions

The named rules in the instruction file every Claude Code and Codex session loads (projects-dotclaude `AGENTS.md`). That file also holds unnamed rules (merging, privacy, storage, closeout format); read it in full for those.
