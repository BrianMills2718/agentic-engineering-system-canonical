Sources: the 2026-11-06 harness grid (127 items), the 2026-11-16 grid review, the consolidation plan, the ecosystem readings, the 2026-09-26 harvest of an earlier AES that lived in a company repository, the Project Meta retirement plan and the 2026-11-19 assessment. It changes to `keep` or `simplify` only when it passes one test: does it help project brains (coding agents working on one project) write correct code or stay aligned with the plan? `keep` needs measured evidence that it worked; `simplify` is for a good idea carried by heavy machinery.

## How to read it

- `drop` means "not carried into AES's core as a part of its own". It does not mean the old system was wrong, and some dropped parts still run as plumbing outside the core.
- "Done in AES?" was checked against `origin/main` of the AES repository (files, specs and commits named in the cell), not guessed. A claim from a document that I could not confirm against the code says so.
- Citations are `file:line`. Keys, all under the AES repository `docs/` unless stated: **G** = `proposals/harness-review/review-page/grid/grid-mapping.json` at the workspace tag `archive/harness-grid-20261106` (stale by design; it shows what the old systems did). **GR** = `planning/harness-grid-review-20261116.md`. **CP** = `planning/aes-consolidation-plan.md`. **EC** = `architecture/ECOSYSTEM.md`. **RP** = `planning/project-meta-retirement-plan.md`. **AS** = `planning/aes-assessment-20261119.md`. **I8** = `planning/item8-rules-and-code2check-20261116.md`. **RC** = `planning/rules-conflicts-20261117.md`. **RT** = `retired/2026-11-12.md`; **RT14** = `retired/2026-11-14.md`. **FP** = `architecture/FEEDBACK_AND_POLICY.md`. **GO** = `architecture/GOAL.md`. **FM** = `failure-modes.md`. **H** = the 2026-09-26 harvest note, `research/synthesis/2026-09-26-inside-success-aes-harvest.md` in AES history (present at commit `37dc876cc3`, since retired; the copy read was byte-identical to that commit).
- A "pilot repository" is a repository where Lockstep (AES's plan-to-code checker) was actually tried. A "trace finding" is one broken link between a requirement, the code that claims it and the test that covers it (AS:51-84). "Edit guard" is the hook that checks a file edit against the plan.

- No cost figures: none were measured for these lessons.
