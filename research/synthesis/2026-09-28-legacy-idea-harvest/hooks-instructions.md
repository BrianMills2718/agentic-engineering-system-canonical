## Failure lessons

- **F1. A self-repair undid a human decision.** Brian: "please turn off all hooks" (2026-09-18); "i ahave been thinking that we should disable these becasue they are causing more porblems then good" (2026-09-22). The #2180 investigation searched ADRs, policy and commits, but not Brian's prompts. It concluded "accidental loss", re-enabled all 54 hooks, and "verified by firing". It was reverted the same day. Lesson: a decision that exists only in a conversation is invisible to automation, and "verified working" proved the wrong claim. Evidence: project-meta#2180 (outcome and correction comments); agent-skills `a44bd1d` then `7ddca02`; `docs/claude-hooks-disabled-2026-09.md`.
- **F2. Why the hooks were turned off: blocking gates stacked up with no escape.** The recorded reason is "Hooks interrupted progress and caused more problems than good (Stop-hook block loops; /goal blocked by disableAllHooks)". 54 hooks were wired: 7 on Stop, 8 on UserPromptSubmit, 16 on SessionStart. Concrete cases:
  - A company-planning Stop gate refused *every* session's end over another live session's repository-global cursor (`CP-LOOP-CLAIM`).
  - The coordination mailbox gate blocked every Bash/Edit/Write, including the acknowledge command itself. This was recorded 4 times, and the only recovery was a subagent.
  - The goal evaluator refused a correct stop 6 times.
  - The destructive-command literal scan has 9 or more friction entries for false positives on search strings (`destructive-command-hook` ×9, `destructive-token-search-false-positive` ×3).

  Lesson: every blocking hook needs a scope limited to the acting session and a self-service exit. Their costs add up per turn. This tempers **B9** ("hooked rules followed 100%"): hooks bound behavior, and the owner still judged them net-negative. Evidence: `project-meta/policy_friction.md` (2026-09-08 entries, `coordination-mailbox-acknowledgement-gate`); `agent-skills/contracts/client-config/hook-manifest.v1.json`.
- **F3. The always-loaded instruction file grows back after each cut.** Workspace root file sizes, from `.claude` git history: 26.5 KB (07-16), cut to 7.0 KB (07-21/25), 35.2 KB (09-08), cut to 10.5 KB (09-10), 32.6 KB (09-26). Each new rule arrives as an incident plus "Brian, date: quote" (for example #60 and #61 on 09-26). Compaction without a gate lasts about two weeks.
- **F4. A size gate that reports and does not stop.** `check_instruction_payload_size.py` run today: root 32,589 of 32,768 bytes, 179 bytes of headroom, "0 fit alongside the root", 149 overflow once combined, "reported, not failed", 4 REGRESSION lines. In Codex's native launch chain every repository's own rules are therefore at risk of truncation, and the checker reports it to no one. This is the same failure class as B6, now in the instruction surface.
- **F5. Hooks executed from a mutable, shared checkout.** A concurrent unclaimed edit made `skill_fork_write_gate.py` briefly absent and hard-blocked every live session. Only 7 of about 49 wired hook commands were registered in the policy registry, so the liveness check could not see it. Fail-open wiring fixes the outage but hides the gap, which is why #407 now counts a missing script as broken. Evidence: `policy_friction.md` `skill_fork_write_gate.py-hook`; `agent-skills/AGENTS.md`.
- **F6. Two generators for one file.** The global `sync-agents-md.sh` PostToolUse hook mirrored `CLAUDE.md` over a repository's own, intentionally different generated `AGENTS.md` (data_contracts). The damage was caught by chance. Separately, a generated projection silently omitted sections (plan 291 Gap). Lesson: exactly one owner per instruction byte. Evidence: `policy_friction.md` 2026-08-20 entry; `docs/plans/291_agents-md-only-instructions.md`.
- **F7. Checks written about the wrong layer.** Manifest-only parity passed while 22 of 39 Codex hooks did not run. `audit_hook_surface.py` classified *itself* wrongly by grepping its own docstring. The hook-surface audit reported unresolved rather than broken for a deleted script. Evidence: `cross_client_config_sync.md`; `audit_hook_surface.py` header comment; #407.

## Not worth harvesting

- The 54 individual Claude hook scripts as features (priority guard, attendance, recall-on-prompt, session brief, and so on). They are machine-specific, and the owner switched them off.
- `continue_on_confident_next.py`, a Stop hook that decides whether to keep going by regex over the closeout's "Recommended next" prose. It infers prose meaning with regex, which the workspace rules forbid, and it is a direct source of Stop-hook loops.
- `read_first_gate.py`'s 1,445-line tiered implementation. The idea (required reading declared structurally in `relationships.yaml`, keyed to the touched path, because "prose is not a gate") belongs to the navigation/context harvest another agent covers. Its code is too coupled to project-meta conventions.
- `manage_client_config.py` Codex trust-hash mechanics (`config/batchWrite`, positional state keys). These are Codex-version-specific plumbing. Keep only idea 4.
- Skill distribution (`sync_skills.py`, `skill_surfaces.yaml` per-client exclude lists). This works, but it solves skill distribution, which v0.2 does not do.
- Hook receipts as a store (`hook_receipts.py`). Already covered by B6: the receipts were written and not read.
