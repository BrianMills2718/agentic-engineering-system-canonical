## Ideas

| 1 | **Progress-bound continuation lease.** Only a digest-bound `behavioral_advance` receipt renews the lease; two distinct `non_outcome` receipts deny the next product write with `recovery_required`, and the result enumerates the only legal next moves (replay/readout, passive inspection, evidence preservation, closeout, one bound recovery). Ordinary approval text and cost telemetry are proven *not* to change the decision; replayed receipts don't renew. Why: stops "approved, so keep going" loops that produce motion but no outcome. | `docs/plans/114_outcome_continuation_lease_enforcement.md`; `enforced_planning/outcome_continuation.py`; `docs/evidence/plan114_outcome_continuation_decisions.json` | tested (both-sign scenarios on the Plan 62 `status-cli-json` consumer); wired observe-only via `scripts/prewrite_claim_gate.py` | execution/orchestration; policy | An AES-governed run makes two or more consecutive plan/repair/rewrite increments with no change to any success-criterion observation. |
| 2 | **Criterion-bound review-ready with rejected-digest tombstones.** An artifact becomes review-ready only when an *independent* verifier attaches passing evidence for **every** frozen criterion on that **exact artifact digest**; evidence never carries across digests; a rejected digest stays permanently ineligible in that outcome lineage; client checklists, turn end, transport success, or a subagent report never count as completion (Plan 137). Why: the observed failure was an agent counting inventory/planning as progress and re-presenting a previously rejected page. Stronger than harvest #4/#18 (they record outcomes; this *forbids* the substitution). | `docs/plans/136_criterion_bound_outcome_gate.md`; `docs/evidence/plan136_criterion_bound_outcome_verification.json`; `docs/plans/137_cross_client_execution_tracking.md`; `docs/evidence/plan137_outcome_completion_stop.json` | tested with an exact real consumer artifact (Plan 52 dashboard) | gap evidence / success-criteria standing (v0.2 has criteria + evidence but no rejected-artifact memory or per-digest binding) | A v0.2 consumer re-submits an artifact a human already rejected, or a gap is marked closed from the producing agent's own evidence. |
| 3 | **Restart delta.** Resume onto the same branch/worktree preserves selected outcome, lease and failure history automatically; *replacing* a stalled approach requires a typed `RestartDeltaV1` that keeps owner/outcome/consumer/journey/predecessor and names one changed causal hypothesis, changed mechanism, bounded action, next observation and stopping condition. Why: stops "start a fresh lane" from erasing the record of what already failed, and forbids retrying the same idea under a new name. | `docs/plans/118_causal_restart_lineage_and_session_handoff_observe.md`; `docs/evidence/plan118_causal_restart_lineage.json` | tested (plan in progress) | execution; plan lifecycle | A v0.2 plan is abandoned and a successor plan targets the same gap/criterion. |
| 4 | **No-passive-waiting over the plan graph.** Distinguish (a) blocked unit with other ready work, (b) path-local integration wait, (c) live session not producing durable progress, (d) genuine whole-goal blocker. "Mark goal blocked" returns `continue_ready_work` + the ready unit when one exists; a real blocker records owner, evidence and resume event and narrows idle write ownership; blocker/handoff events do **not** renew the progress lease. Stronger, mechanized version of harvest #5 (which is a design lesson only). | `docs/plans/110_no_passive_waiting_enforcement.md`; `docs/evidence/plan110_npw03_outcome_scenario.json`, `plan110_npw02_owner_calibration.json` | tested (NPW-01..03 accepted) | execution; plan validation (`aes plan` knows units but not readiness) | A v0.2 run reports "blocked" while its accepted plan still contains an unblocked item. |

Open design note (MP-019): path overlap misses "same bug, different files" — three sessions fixed one root cause three ways. | `docs/plans/132_overbroad_claim_narrowing.md`; `docs/evidence/plan132_claim_narrowing.json`; `ISSUES.md` MP-019 | observed in a generated consumer through installed entrypoints; MP-019 design | multi-agent coordination (v0.2 has none) | Two agent sessions write the same v0.2 consumer concurrently. |

## Failure lessons

1. **The escape hatch became the main path.** `[Unplanned]` commits rose from 7% of commits in 2026-07 (20/304) to 36% in 2026-08 (134/369) to 61% in 2026-09 (269/440), while `[Plan #…]` commits fell from 115 to 52. The planning lifecycle's cost pushed real work through the bypass. This is stronger evidence for harvest A7's "sanctioned route must need fewer blanks than the escape hatch." Evidence: `git log --format='%ad|%s' --date=format:%Y-%m` at `9963dc4`.
2. **Admission by allowlisting commands became an endless exception stream.** 17 `Admit …` commits (e.g. "Admit claimless control inspection" #575, "admit absolute lifecycle close commands" #572, "admit read-only Inside Success gh wrapper" #561) and four deadlock fixes (`b107254`, `43a56cf`, `83db680`, `de2aa7f`). Each new legitimate command shape was a false block until patched. Lesson: a gate that must recognize every safe command will always lag; prefer gating a small set of state transitions.
3. **Each control passed alone; together they did not.** Plan 108's source and consumer evidence was accepted piece by piece, then the 2026-09-16 review found nobody had shown the combined hooks allow recovery and resumed work; PW-06 was added as a hard prerequisite and fleet rollout stopped. Evidence: `docs/plans/108_prewrite_claim_enforcement.md` §PW-04/PW-06.
4. **An append-only hot store turned into hook timeouts.** 1,692 terminal YAML files gave 5.29–8.34 s PreToolUse callbacks; SessionStart reached 9.47 s; one legacy drain went over 60 s under a single lock. Fix: archive terminal records out of the synchronous registry. Evidence: `docs/plans/131_terminal_closeout_and_hook_hotpath.md`, `docs/plans/127_turn_end_safety_and_hook_feedback.md`, commit `d275f70` ("Remove claim scans from PreToolUse").
5. **Five evaluation rounds never produced a promotable learning detector.** The synthetic pilot was rejected because no native unseen cases showed it was representative. Native corpus v1 was invalid: its manifest left out an in-scope event and mislabeled its only correction. v2 was a valid fail (10/14 recall, 1 false positive). v5 was signed off as a route **rejection** (3 false positives). The detector stays manual/off. Lessons: sampling and label errors in the eval corpus are as serious as model errors; a model call cannot sit in a 3 s hook. Evidence: `docs/plans/135_correction_learning_gate.md` (~l.395-510), `docs/evidence/plan135_native_corpus_signoff.md`, `plan135_native_v5_signoff.md`.
6. **A design built on an unverified premise.** Plan 126 (atomic projection refresh) assumed claim creation wrote outside the registry lock. Reading the source disproved this, and the plan was superseded without implementation. Evidence: `docs/plans/126_atomic_projection_refresh.md` ("Final Disposition").
7. **A generic control plane was out of proportion to the problem.** Plan 71 (definition pack, resolver, schemas, exception model, adapters, shadow pilot) was rejected by the 2026-07-16 policy-friction audit in favor of a direct, observable fix. Evidence: `docs/plans/71_effective-policy-resolution-pilot.md` §Disposition.
8. **Closeout deleted unmerged work.** `session-close` treated a clean worktree as safe to delete and ran `git branch -D` without proving integration. It also lost its root anchor when the worktree was removed before the branch. Severity critical. Evidence: `ISSUES.md` MP-016; `docs/plans/59_…`.
9. **The installer copied a dead module into seven repositories.** `hook_wiring.py`'s support-file list copied `prewrite_claim_gate.py` into every governed repo, and the audit *required* the file to be present, so the orphan was spread and protected at the same time. Evidence: commit `f404a5a` (#129). Lesson for v0.2 topology: an installer's copy list is a topology declaration and needs the same orphan check.
10. **A safety rule blocked the one safe path.** The shared-append escape-hatch refusal was added and removed the same day because it refused the pathspec single-file commit, which cannot sweep in another writer's staged files and was the documented recovery route. The removed code was replaced with a comment explaining why, so nobody re-adds it on the same reasoning. Evidence: commit `601db0a` (#203).
11. **An expiry filter hid abandoned value.** See idea 15. Evidence: commit `f969307`.
12. **A count-based sensor measured the wrong thing.** Declaring tests and scripts as entrypoints made every tested module count as "reachable," so the check could never see unwired work. Evidence: `docs/plans/75_…`.
13. **An ordinary turn end was treated as repository closeout.** The Stop hook blocked normal turns whenever a derived projection was stale, which penalized agents for a crash window in the framework itself. Evidence: `docs/plans/127_…` §Gap.

## Not worth harvesting

- `relationships.yaml` doc coupling, required-reading/navigation gates, truth-surface validators (Plans 03–10, 18, 38, 41): tied to the old authority model and already rejected as a provider in `21-provider-bindings`. v0.2's target/observation split covers the static-vs-runtime distinction in `STATIC_GRAPH_AND_RUNTIME_TRUTH.md`.
- Cross-client mailbox and acknowledgement (Plans 67/68/100/106): the transferable part, recording delivered, observed and acknowledged separately, is already covered by harvest #3's expected/emitted/acknowledged. The rest is Codex/Claude plumbing.
- Plan-number reservation, plan status index/projection (57, 102), ops archive, CLAUDE.md cleanup, ecosystem dashboard/status renderer (21, 50), Mac mini transfer (23): ecosystem housekeeping.
- ADR 0004 ("gate YAML is the documentation") and ADR 0005 (hierarchical compression): v0.2's `.aes/target.yaml` authority and context packet already hold these positions.
- Self-measurement/ROI (Plan 22): metric taxonomy only, with no retained measurement. Harvest #23 is the stronger version.
- Artifact creation policy, context packet, installer: already dispositioned in `18-internal-provider-evaluation`.
